# Angular Material Data Grid Documentation

This document provides detailed documentation on how to use the Angular Material Data Grid and its features.

## Installation

As this package is not available on the npm registry, you need to build it from the source.

1.  **Clone the repository:**
    ```bash
    git clone https://github.com/troyaaronjones/angular_material_data_grid.git
    cd angular_material_data_grid
    ```

2.  **Install dependencies:**
    ```bash
    npm install
    ```

3.  **Build the library:**
    ```bash
    npm run lib:build
    ```

4.  **Navigate to the distribution directory and link the package:**
    ```bash
    cd dist/angular-material-data-grid
    npm link
    ```

5.  **Navigate to your project and link the package:**
    ```bash
    cd /path/to/your/project
    npm link angular-material-data-grid
    ```

6.  **Install Angular Material** (if not already installed):
    ```bash
    ng add @angular/material
    ```

7.  **Import Module**
    ```typescript
    import { AngularMaterialDataGridModule } from 'angular-material-data-grid';

    imports: [
      // ...,
      AngularMaterialDataGridModule
    ]
    ```

## Basic Usage

### HTML

```html
<amdg-grid
  [headings]="headings"
  [url]="url"
  [serverSidePagination]="true"
  (responseEmit)="responseReceived($event)">
</amdg-grid>
```

### TypeScript

For a complete example of the component's inputs and outputs, please refer to the source code in this repository.

## Column Selection

The grid supports showing and hiding columns, as well as reordering them. To enable this feature, set the `columnControl` input to `true`.

```html
<amdg-grid [columnControl]="true" ...>
</amdg-grid>
```

When `columnControl` is `true`, a button will appear above the grid that opens a dialog for managing columns.

The visibility of each column is controlled by the `show` property in the `GridHeadingInterface`.

*   If `show` is `undefined` (not set), the column will always be visible and cannot be hidden by the user.
*   If `show` is `true`, the column will be visible by default, and the user can hide it.
*   If `show` is `false`, the column will be hidden by default, and the user can show it.

## Theming

The grid is styled using SCSS and can be customized by overriding the SCSS variables. The main files for theming are:

*   `projects/angular-material-data-grid/src/lib/variables.scss`: Contains color and typography variables.
*   `projects/angular-material-data-grid/src/lib/angular-material-data-grid-utilities.scss`: Contains utility classes for styling.

To customize the theme, you can override these variables in your own SCSS file and import it after the grid's styles.

## Filter Types

The grid provides different types of filters based on the column's `type` and `filterType` properties in the `GridHeadingInterface`.

### String Filter

This is the default filter for columns with `type: 'string'`. It provides a text input to filter by string operations like "contains", "starts with", "ends with", etc.

```typescript
{
  fieldName: 'name',
  display: 'Name',
  type: 'string'
}
```

### Number Filter

This is the default filter for columns with `type: 'number'` or `type: 'currency'`. It provides a number input to filter by a specific number or a range.

```typescript
{
  fieldName: 'age',
  display: 'Age',
  type: 'number'
}
```

### Date Filter

This is the default filter for columns with `type: 'date'`. It provides a date picker to filter by a specific date or a date range.

```typescript
{
  fieldName: 'dob',
  display: 'Date of Birth',
  type: 'date'
}
```

### Multi-select Filter

The multi-select filter can be used for columns with `type: 'string'` by setting `filterType: 'multi-select'`. This filter allows users to select one or more values from a dropdown list. The options for the multi-select can be provided either locally or fetched from a remote URL.

#### Local Data

To provide the options locally, set `source: 'internal'` and provide the options in the `optionsObject`.

```typescript
{
  fieldName: 'status',
  display: 'Status',
  type: 'string',
  filterType: 'multi-select',
  other: {
    selectionMode: 'multiple',
    source: 'internal',
    optionsObject: [
      { display: 'Active', value: 'active' },
      { display: 'Inactive', value: 'inactive' }
    ]
  }
}
```

#### Remote Data

To fetch the options from a remote URL, set `source: 'external'` and provide the URL, key, and value properties.

```typescript
{
  fieldName: 'category',
  display: 'Category',
  type: 'string',
  filterType: 'multi-select',
  other: {
    selectionMode: 'single',
    source: 'external',
    url: 'https://api.example.com/categories',
    key: 'name',
    value: 'id'
  }
}
```

### Tag Filter

The tag filter is similar to the multi-select filter but is designed for a large number of options. It can be enabled by setting `filterType: 'tag'`.

```typescript
{
  fieldName: 'tags',
  display: 'Tags',
  type: 'string',
  filterType: 'tag'
}
```

## Sorting

Sorting is enabled by default for all columns. It can be disabled for a specific column by setting `disableSorting: true` in the `GridHeadingInterface`.

```typescript
{
  fieldName: 'id',
  display: 'ID',
  type: 'number',
  disableSorting: true
}
```

When a user clicks on a column header, the grid will emit the `sortChangedEmit` event with the sort information, and the grid will be updated accordingly.

## Pagination

The grid supports both client-side and server-side pagination.

### Client-side Pagination

Client-side pagination is the default behavior. The grid will fetch all the data from the URL and then paginate it on the client.

### Server-side Pagination

To enable server-side pagination, set the `serverSidePagination` input to `true`.

```html
<amdg-grid [serverSidePagination]="true" ...>
</amdg-grid>
```

When server-side pagination is enabled, the grid will send a request to the URL with the page number and page size. The API is expected to return the data for the requested page.

The `pageSizes` and `pageSize` inputs can be used to configure the paginator.

## Server Binding

The grid fetches data from the URL specified in the `url` input. The `entity` input can be used to send additional data with each request.

When using server-side pagination, the grid will send a POST request to the `url` with a body that looks like this:

```json
{
  "entity": {},
  "page": 1,
  "perPage": 100,
  "filters": [],
  "sort": "asc",
  "sortField": "name"
}
```

The API is expected to return a response in the following format:

```json
{
  "payload": {
    "gridData": [],
    "totalCount": 0,
    "other": {}
  },
  "statusCode": 200,
  "success": true
}
```

## Child Grids (Master-Detail)

The grid supports a master-detail view where a row can be expanded to show more information or a child grid. To enable this feature, set the `expandable` input to `true` and provide the `expandableConfig`.

```html
<amdg-grid [expandable]="true" [expandableConfig]="expandableConfig" ...>
</amdg-grid>
```

The `expandableConfig` object has the following properties:

| Property            | Type      | Description                                                                                             |
|---------------------|-----------|---------------------------------------------------------------------------------------------------------|
| `type`              | `'html' \| 'grid'` | The type of content to show in the expanded section.                                                    |
| `multipleExpansion` | `boolean` | Whether multiple rows can be expanded at the same time.                                                 |
| `template`          | `string`  | The HTML template to use when `type` is `'html'`. You can use placeholders like `{{name}}` to show data from the row. |
| `childGrid`         | `any`     | The configuration for the child grid when `type` is `'grid'`. This is another `amdg-grid` component.     |
